# Спецификация: система уровней, опыта (XP) и Combo

## 0. Задача

Реализовать в `rth-agriculture` систему долгосрочной прогрессии игрока:

* XP;
* уровни;
* Combo / streak безошибочного написания;
* визуальное начисление XP после очистки грядки/поля;
* минималистичное отображение текущего уровня и XP на главной карте;
* juice-анимации Combo и повышения уровня.

Система должна быть очень простой для понимания игроком:

> правильный штрих приносит XP; ошибка отнимает XP; аккуратное письмо позволяет немного увеличить награду через Combo.

XP не должен превращаться в отдельную сложную валюту или доминировать над основной механикой изучения иероглифов.

---

# 1. Основные термины

## Иероглиф

Один полностью написанный kanji является атомарной единицей начисления XP.

Игрок начинает писать иероглиф, проводит все необходимые штрихи, допускает или не допускает ошибки, после чего иероглиф считается завершённым.

## XP

Опыт — постоянная величина аккаунта игрока.

XP:

* никогда не сбрасывается;
* используется только для вычисления уровня;
* может продолжать расти бесконечно;
* не является расходуемой валютой.

## Уровень

Уровень — долгосрочный индикатор прогресса игрока.

Уровни:

* начинаются с `1`;
* hard cap отсутствует;
* не должны блокировать возможность заниматься повторениями;
* пока не дают дополнительных gameplay-способностей;
* являются прежде всего мета-прогрессией и источником ощущения роста.

## Combo

Combo — количество **полностью написанных подряд иероглифов без единой ошибочной попытки штриха**.

Combo — session-state, а не постоянная прогрессия.

---

# 2. Начисление XP за иероглиф

XP начисляется после завершения иероглифа.

Для одного иероглифа:

```text
baseXp = correctStrokeCount - errorCount
kanjiXp = max(1, baseXp)
```

То есть:

```text
+1 XP за каждый правильный штрих
-1 XP за каждую ошибку
минимальная итоговая награда за завершённый иероглиф = +1 XP
```

Примеры:

```text
6 штрихов, 0 ошибок → +6 XP
6 штрихов, 1 ошибка  → +5 XP
6 штрихов, 4 ошибки → +2 XP
6 штрихов, 12 ошибок → +1 XP
```

Важно:

* нельзя получить 0 XP за завершённый иероглиф;
* нельзя получить отрицательный XP за завершённый иероглиф;
* XP начисляется именно после завершения иероглифа;
* внутренняя статистика может отдельно считать правильные штрихи и ошибки.

---

# 3. Combo

## 3.1. Что увеличивает Combo

После завершения иероглифа:

```text
если errorCount === 0:
    combo += 1
иначе:
    combo = 0
```

Combo считается **по иероглифам, не по штрихам**.

Например:

```text
自 — 6 правильных штрихов, 0 ошибок
→ combo +1

следующий kanji — 13 правильных штрихов, 0 ошибок
→ combo +1

следующий kanji — хотя бы одна ошибка
→ combo = 0
```

Ошибка должна сбрасывать Combo даже в том случае, если игрок затем успешно завершил этот же иероглиф.

---

# 4. XP-бонусы за Combo

Combo не должен существенно менять экономику XP.

Нельзя использовать постоянный multiplier:

```text
x1.2
x1.5
x2
```

Вместо этого использовать небольшие одноразовые milestone rewards.

Стартовая таблица:

|            Combo |  Бонус |
| ---------------: | -----: |
|                3 |  +1 XP |
|                5 |  +2 XP |
|               10 |  +3 XP |
|               20 |  +5 XP |
|               50 |  +8 XP |
|              100 | +12 XP |
| далее каждые +50 | +10 XP |

Бонус выдаётся **один раз при пересечении конкретного milestone**.

Пример:

```text
combo 9 → 10
получить +3 XP

combo 10 → 11
дополнительного XP нет
```

После 100:

```text
150 → +10 XP
200 → +10 XP
250 → +10 XP
...
```

Combo bonus добавляется поверх `kanjiXp`.

```text
earnedXp = kanjiXp + comboMilestoneBonus
```

---

# 5. Juice для Combo

Экономическая награда Combo намеренно маленькая.

Визуальная и звуковая награда, наоборот, должна ощущаться значительно сильнее.

Минимальные milestones:

### Combo 3

Первое заметное включение режима Combo.

Использовать:

* короткий glow;
* лёгкий particle burst;
* изменение состояния индикатора Combo;
* короткий приятный sound cue.

### Combo 5

Немного сильнее:

* световой sweep;
* небольшой всплеск частиц;
* анимация числа Combo.

### Combo 10

Первый действительно заметный milestone:

* вспышка;
* частицы;
* небольшой screen/UI pulse;
* более выраженный звук.

### Combo 20

Можно временно добавить дополнительный визуальный слой:

* ветер;
* листья;
* искры;
* glow кисти/эффекта удара.

### Combo 50

Редкое событие.

Допускается короткая celebratory animation.

### Combo 100

Очень редкое событие.

Полноценный, но короткий celebration moment.

---

# 6. Использование генерации изображений

Codex должен использовать доступные ему навыки генерации изображений при реализации визуальной части.

Перед созданием новых assets:

1. исследовать существующие изображения и UI-assets проекта;
2. сохранить текущий визуальный язык:

   * тёмный зелёный;
   * пергамент;
   * приглушённое золото;
   * китайский сад;
   * serif typography;
   * спокойная premium-fantasy эстетика;
3. не вводить мультяшные, неоновые или modern-mobile-game элементы.

При необходимости создать:

* декоративный Combo-emblem;
* FX sprites;
* небольшой glow;
* particle textures;
* level-up emblem;
* минимальный level badge.

Сначала желательно сделать 1–2 mockup/composition images и сверить их с существующим интерфейсом проекта, затем нарезать/генерировать необходимые assets.

Не нужно генерировать огромные панели, если эффект можно реализовать CSS/canvas/particles средствами приложения.

# 7. Формула уровней

Стоимость перехода от текущего уровня `L` к следующему:

```text
xpForNextLevel(L) = 100 + 20 × (L - 1)
```

Примеры:

| Текущий уровень | XP до следующего |
| --------------: | ---------------: |
|               1 |              100 |
|               2 |              120 |
|               3 |              140 |
|               5 |              180 |
|              10 |              280 |
|              20 |              480 |
|              50 |             1080 |
|             100 |             2080 |

Рост линейный.

Не использовать exponential curve.

---

# 8. Total XP и вычисление уровня

Уровень следует вычислять из total XP детерминированно.

Обозначим:

```text
n = level - 1
```

Суммарный XP, необходимый для достижения уровня `L`:

```text
totalXpForLevel(L)
= 100n + 10n(n - 1)
= 10n² + 90n
```

где:

```text
n = L - 1
```

Примеры:

```text
Level 1 → 0 XP
Level 2 → 100 XP
Level 3 → 220 XP
Level 5 → 520 XP
Level 10 → 1620 XP
Level 50 → 28420 XP
Level 100 → 106920 XP
```

Предпочтительная модель persistence:

```ts
totalXp: number
```

Уровень и progress вычислять из него.

Можно кэшировать `level`, но `totalXp` должен оставаться source of truth.

---

# 9. Progress внутри текущего уровня

Нужно вычислять:

```text
currentLevel
xpAtLevelStart
xpAtNextLevel
xpInsideLevel
xpNeededInsideLevel
```

Например:

```text
totalXp = 241
level = 3

level 3 начинается с 220 XP
следующий уровень требует ещё 140 XP

xpInsideLevel = 21
xpNeededInsideLevel = 140
```

UI можно представить как:

```text
21 / 140 XP
```

или, если существующая архитектура удобнее, абсолютные значения:

```text
241 / 360 XP
```

Выбрать один формат и использовать последовательно.

Предпочтительно показывать progress **внутри уровня**, потому что он легче читается игроком.

---

# 10. Level-up

Если одно начисление XP пересекает несколько уровней, необходимо обработать все переходы.

Пример:

```text
level 4
80 XP до level 5

игрок заработал +310 XP
```

Система должна:

1. заполнить текущий progress bar;
2. проиграть `Level 5`;
3. перенести остаток XP;
4. при необходимости заполнить следующий bar;
5. проиграть `Level 6`;
6. закончить на правильном остатке XP.

Не показывать:

```text
Level 4 → Level 6
```

одним мгновенным переходом.

Каждый level-up — отдельный reward beat.

---

# 11. Где показывается XP

## Во время написания иероглифа

Не показывать постоянный level progress bar.

Основной gameplay должен оставаться чистым.

Можно показывать:

* краткий `+N XP` после завершения иероглифа;
* Combo;
* Combo milestone effects.

Но эти элементы должны быстро исчезать.

Главная задача gameplay screen — написание и уничтожение сорняка.

---

# 12. Экран завершения: «Сад снова дышит»

После очистки текущей грядки/поля показывать summary screen.

Существующий экран `Сад снова дышит` дополнить XP.

Структура:

```text
ПОЛЕ ОЧИЩЕНО

[цветок]

Сад снова
дышит

Все доступные сорняки уничтожены.
Новые повторения появятся здесь
по расписанию памяти.

────────────

Правильные штрихи       +42 XP
Ошибки                   -3 XP
Комбо                    +2 XP

Итого                   +41 XP

────────────

[LEVEL 7]   [XP progress bar]
             241 / 300 XP

[Вернуться к карте]
```

Цифры выше — только пример.

XP должен анимированно добавляться в progress bar.

Последовательность:

1. экран появляется;
2. строки результата могут проявляться последовательно;
3. отображается total XP earned;
4. `+N XP` переливается/зачисляется в level bar;
5. если происходит level-up — отдельная celebration animation;
6. после animation активируется/становится акцентной кнопка возврата.

---

# 13. Главная карта

На главной карте показывать **только минимальный постоянный progress**.

Не добавлять:

* «До уровня 8»;
* «Очищено полей»;
* «Готово к повторению»;
* лишние stats;
* дополнительные progression widgets.

Под существующим header разместить очень компактный progress element:

```text
(7)  ━━━━━━━━━━━━━━━   241 / 300 XP
```

Где:

* `7` — текущий уровень;
* рядом тонкая XP-полоска;
* справа текущий XP progress.

Без дополнительного текста.

Этот элемент должен занимать минимальную высоту и не перекрывать карту.

Можно использовать тонкую золотую/пергаментную обводку либо вообще разместить элементы непосредственно на тёмно-зелёном фоне.

Главная карта должна оставаться визуальным центром экрана.

# 14. Persistence

Нужно хранить как минимум:

```ts
interface PlayerProgress {
  totalXp: number;
}
```

Session-state:

```ts
interface SessionProgress {
  combo: number;
  bestComboThisSession: number;
  correctStrokeCount: number;
  errorCount: number;
  earnedXp: number;
  comboBonusXp: number;
}
```

Для статистики дополнительно желательно:

```ts
lifetimeCorrectStrokes
lifetimeErrors
lifetimeCompletedKanji
bestComboEver
```

---

# 15. События

Желательно сделать XP-систему event-driven.

Примерные domain events:

```text
stroke.correct
stroke.error

kanji.completed

combo.changed
combo.milestoneReached
combo.broken

xp.earned
level.up

garden.sessionCompleted
```

Логика начисления XP не должна жить непосредственно внутри UI-компонента.

---

# 16. Важный edge case: подсказка следующего штриха

Если в игре есть кнопка:

```text
Показать следующий штрих
```

не считать использование подсказки ошибкой автоматически, если текущая логика приложения не определяет её как ошибку.

Но желательно сохранить:

```text
hintUsed: boolean
```

для будущей статистики/achievement system.

Не менять XP-экономику подсказок в рамках этой задачи без необходимости.

---

# 17. Не делать

Не внедрять в рамках этой задачи:

* stamina;
* energy;
* cooldown;
* path points;
* XP multipliers;
* XP boosters;
* daily XP;
* XP за login;
* XP за achievement;
* платные boosts;
* level-gated право писать иероглифы;
* hard cap уровня.

# 19. Acceptance criteria

Функция считается реализованной, если:

* каждый законченный kanji приносит минимум 1 XP;
* correct stroke = +1 XP;
* error = -1 XP;
* Combo считается по полностью безошибочным kanji;
* Combo milestone rewards начисляются корректно;
* уровень вычисляется по указанной формуле;
* уровни не имеют hard cap;
* XP сохраняется между сессиями;
* экран `Сад снова дышит` показывает breakdown XP;
* progress bar визуально принимает заработанный XP;
* level-up имеет отдельную animation;
* главная карта показывает только level + progress bar + XP;
* игровое поле не перегружено мета-UI;
* визуальные элементы соответствуют текущему стилю проекта;
* для новых декоративных assets Codex использует свои image-generation skills.
